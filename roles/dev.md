Cares about: what is wrong in the code, where (file:line), why, and the fix.
Jargon OK: all programming terms (N+1, race condition, null, closure, migration).
Leave out: business impact unless asked, test plans, timelines.
Technical part: files and lines, the code path, why it is right or wrong, the evidence (tests, queries, numbers).
End with: the fix or next code step.
